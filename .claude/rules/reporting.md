# 성과 보고서 포맷

## 간소화 버전 (오케스트레이터 직접 출력 — easy/medium)
easy/medium 문제는 reporter 에이전트 스폰 없이 오케스트레이터가 직접 출력.
```
═══════════════════════════════════════
  문제: <name> | 카테고리: <cat> | 난이도: <difficulty>
  플래그: <flag>
  소요: <시간> | 시도: <N>회 | 에이전트: <사용된 에이전트 목록>
  기술: <핵심 기법 1줄>
  학습: <새로 알게 된 것 1줄>
═══════════════════════════════════════
```
이 형식은 ~200 output tokens. reporter 에이전트 스폰 시 ~20k 시스템 프롬프트 비용 절약.

## 상세 버전 (reporter 에이전트 — hard만)

플래그 보고 시 아래 형식을 반드시 출력. 한글로.

## 측정 기준

### 시간
- 소요 시간: checkpoint.json 첫 timestamp ~ FLAG_FOUND timestamp
- 시도 횟수: memory/failures.md 엔트리 수 + 최종 성공 1회

### 토큰 측정 방법
정확한 수치 대신 **합리적 추정**으로 기록:
- 오케스트레이터: 인테이크 과정의 도구 호출 수 × 평균 응답 크기
- 디컴파일/분석 출력: 줄 수 기반 (1줄 ≈ 5 토큰)
- 핸드오프 프롬프트 크기: 직접 측정 가능
- 재시도: 횟수 × 평균 시도당 토큰
- solver 코드 작성: solve.py 줄 수 × 5
- reporter: 보고서 출력 길이

### 비용은 토큰으로 표기
달러 금액 대신 **토큰 수(Xk)**로 표기. opus 토큰은 sonnet 대비 5배 비싸므로 별도 표기.

### 모델/Effort 적절성 분석 (MANDATORY)
**반드시 포함해야 하는 항목:**
1. 실제 사용 모델 vs 대안 모델의 **비용 환산 비교 테이블** (opus=sonnet×5)
2. 저렴한 모델의 **성공 확률 추정** + 근거
3. **기대값 비교**: (확률 × 성공비용 + (1-확률) × 재시도비용) vs 비싼 모델 직행
4. **contest/practice 모드별 판단**: 시간 리스크 vs 토큰 비용 트레이드오프
5. **이득/낭비 요소** 구체적 나열

참고 모범 사례: `challenges/Mirage/report.md`

### 다음번 예상
- 시간/토큰/비용 모두 구체적 수치
- 근거: 각 항목별 절약량 + 어떤 에이전트를 생략/축소할 수 있는지

### 비효율 분석
- 전체 토큰의 50% 이상을 쓴 에이전트/구간 반드시 식별
- 불필요한 재시도, 과도한 출력, 핸드오프 비대화 등 원인
- 다음 풀이에서 적용할 개선 제안
